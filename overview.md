# Script2Stock — Overview

## Purpose
Script2Stock converts a You‑script (title + long text) into a storyboard of ranked stock‑media assets (images/videos). The user receives a web interface where they can browse, select, or reject assets per scene, and the choices feed back into improved future suggestions.

---

## High‑Level Architecture

| Layer | Technology |
|---|---|
| **Backend** | FastAPI (Python) running on `http://localhost:8000` |
| **Database** | SQLite via SQLModel (`backend/data/cache.db`) |
| **Cache** | API response cache (TTL 6‑24h) + on‑disk thumbnails (`backend/data/thumbnails/`) |
| **AI/ML** | sentence‑transformers (`all‑MiniLM‑L6‑v2`) for semantic embeddings (optional, degrades to keyword‑only); spaCy `en_core_web_sm` for entity/noun extraction (optional, regex fallback works) |
| **Frontend** | React + Vite on `http://localhost:5173`, proxies `/api` and `/thumbnails` to the backend |
| **One‑click start** | `start-app.bat` launches backend first, waits for health check, then starts frontend and opens the browser |

The whole system is **local‑first**: no paid cloud services are required. Pexels and Pixabay need API keys (optional); Wikimedia works without keys.

## Data Model (SQLite)

Core tables (SQLModel / SQLAlchemy‑style):

| Table | Key fields | Purpose |
|---|---|---|
| **Script** | `id`, `title`, `text`, `created_at` | User‑provided script |
| **Scene** | `id`, `script_id`, `index`, `narration`, `start_char`, `end_char` | Logical segments of the script (generated by the scene splitter) |
| **SearchQuery** | `id`, `scene_id`, `query`, `rank` | Rewritten search queries per scene (3‑6 per scene) |
| **MediaAsset** | `id`, `scene_id`, `provider`, `provider_id`, `title`, `description`, `url`, `download_url`, `thumbnail_url`, `cached_thumbnail`, `media_type`, `width`, `height`, `duration`, `license`, `license_url`, `creator`, `attribution_required`, `score`, `status` | Ranked stock‑media candidates |
| **Feedback** | `id`, `scene_id`, `media_id`, `action` (`select`/`reject`), `query_used`, `created_at` | User select/reject actions that re‑weight queries |
| **ApiCache** | `key`, `response_json`, `created_at`, `ttl_seconds` | HTTP response cache for provider searches |
| **EmbeddingCache** | `text_hash`, `text`, `vector` (`float32`), `model`, `created_at` | SQLite cache for sentence embeddings |
| **StoryboardSave** | `id`, `script_id`, `state_json`, `created_at` | Saved UI state (persisted scroll/selection) |

Relationships: a Script has many Scenes; a Scene has many SearchQueries and many MediaAssets; Feedback links a Scene + MediaAsset + action.

## End‑to‑End Flow (Generation Job)

1. **POST /api/scripts** – user supplies `{title, text}`.
2. Job created (`jobs.create_job()`) and `run_generation_job` runs in the background.
3. **Script → Scenes**: `scene_splitter.split_script(text)` → paragraph → sentence boundaries → greedy merge of 1‑3 sentences targeting 15‑40 words → `Scene` rows with `narration`, `start_char`, `end_char`.
4. **Scenes → Queries**: For each scene narration, `query_generator.generate_queries(narration)` produces 3‑6 search queries using:
   - spaCy NER (`PERSON, ORG, GPE, EVENT, WORK_OF_ART, PRODUCT, FAC`)
   - noun‑chunk extraction
   - verb‑object bigrams
   - concept expansions (e.g., "ai" → "artificial intelligence", "machine learning", "neural network")
   - regex fallback if spaCy unavailable
5. **Queries → Providers**: For each query, three providers are searched concurrently (Pexels, Pixabay, Wikimedia). Each provider returns up to `per_page` NormalizedMedia items. Results are cached in SQLite (`api_cache` with TTL 6h default, 24h for Pixabay).
6. **Fuse & Rerank** (`core.pipeline.fuse_and_rerank`):
   - **RRF** (Reciprocal Rank Fusion): each (query, provider) list votes `1/(k+rank)` with `k=60`; scores summed across lists.
   - **Junk filtering** (`core.junk.provider_cleanup`) removes watermarks, vectors, etc.
   - **Asset ranking** (`core.ranker.rank_assets`): per‑asset score = `keyword_overlap*0.5 + orientation*0.2 + resolution*0.2 + type_pref*0.1`.
   - **Semantic rerank** (`core.rerank.rerank`): final score = `(1‑w)*keyword + w*semantic` where `w = SEMANTIC_WEIGHT` (default 0.6). Keyword score from `score_asset`; semantic score from MiniLM embeddings (cached in SQLite). Falls back to keyword‑only if embeddings unavailable.
   - **Feedback boost** (Layer 6): user select/reject actions add +0.5 / –0.25 to query multipliers (range 0.5‑2.0), applied after RRF then rerank.
7. **Storyboard diversity** (`core.diversity.enforce_ratio` + `core.diversity.diverse_rank`):
   - Each asset gets a "coarse tag" (top noun from title, or first meaningful word).
   - A penalty `1/(1+n)` is applied where `n` = how many previous scenes already had that tag → avoids five forest clips in a row.
   - Video‑ratio nudging: each scene’s top‑N is adjusted toward `TARGET_VIDEO_RATIO` (default 0.6) by swapping in videos and swapping out images.
8. **Persist**: Ranked `MediaAsset` rows stored per scene, thumbnails downloaded best‑effort to `backend/data/thumbnails/`.
9. Job progress updated per scene; on completion `job.status = "done"`.

## Scene Splitter (`scene_splitter.py`)

- **Input**: full script text.
- **Rules**:
  - Paragraph breaks (blank lines) are hard scene boundaries.
  - Within a paragraph, split on sentence boundaries (`(?<=[.!?…])\s+(?=[A-Z0-9"‘([])`).
  - Merge sentences into scenes of 1‑3 sentences, targeting 15‑40 words.
  - Track character offsets relative to original text.
- **Output**: `list[SceneChunk]` each with `narration`, `start_char`, `end_char`.

---

## Query Generation (`query_generator.py`)

- **Primary**: spaCy `en_core_web_sm` for:
  - Named‑entity extraction (wanted labels: PERSON, ORG, GPE, EVENT, WORK_OF_ART, PRODUCT, FAC).
  - Noun‑chunk frequency list.
  - Verb‑object pairs (verb lemma + direct object).
- **Regex fallback**: if spaCy fails, simple word‑frequency extraction.
- **Concept expansions** (`CONCEPT_EXPANSIONS` dict): e.g., "crypto" → ["cryptocurrency", "bitcoin", "blockchain"].
- **Output**: 3‑6 search queries per scene, guaranteed at least 3 (padded with "stock footage" if needed).

---

## Asset Scoring & Ranking (`ranker.py`)

Per‑asset score breakdown:

```
score = keyword_overlap * 0.5
       + orientation_match * 0.2
       + resolution_score * 0.2
       + media_type_preference * 0.1
```

- **keyword_overlap**: Jaccard‑like overlap between asset's title+description tokens and scene's narration tokens (stopwords removed).
- **orientation_match**: 1.0 if landscape (width ≥ height) matches preferred, else 0.3.
- **resolution_score**: logarithmic function of megapixels; 0 MP → 0.2, ≥8 MP → 1.0.
- **media_type_preference**: slight image/video bias (default neutral).

**`rank_assets`** also deduplicates on `(provider, provider_id)` and on `download_url`, penalising duplicates by –0.5.

---

## RRF Fusion (`core.fusion.rrf_fuse`)

- For each (query, provider) list, every position `rank` (1‑based) adds `1/(k+rank)` to that media‑id's cumulative score, with `k = RRF_K = 60` (from config).
- Items appearing in many lists (multiple queries or multiple providers) naturally rank higher.
- Deterministic: same input → same output order.

---

## Semantic Reranking (`core.rerank.rerank`)

- Computes keyword scores (via `ranker.keyword_scores`) and MiniLM semantic scores (via `providers.ai.embeddings.semantic_scores`).
- Blend: `(1‑w)*keyword + w*semantic`, `w = SEMANTIC_WEIGHT` (default 0.6).
- If embeddings are unavailable (model missing), returns keyword scores only.
- Sorts items by blended score, keeps top‑`top_n` (default 12).

---

## Diversity Enforcement (`core.diversity.py`)

- **coarse_tag**: extracts top noun from asset title (spaCy noun head, else first meaningful word). Used as a “tag”.
- **diverse_rank**: walks each scene's candidate list, applies penalty `1/(1+n)` where `n` = how many earlier scenes already had that tag. This penalises repeated themes (e.g., five forest clips in a row).
- **enforce_ratio**: nudges each scene's top‑N toward the target video ratio (`TARGET_VIDEO_RATIO = 0.6`). It scans the top‑N, counts videos, and swaps in videos from the rest pool while swapping out images, until the ratio is met.

---

## Feedback Loop (`core.feedback.py`)

- **record_feedback**: stores a `Feedback` row (`select` or `reject`).
- **reweight_queries**: per‑query multipliers in [0.5, 2.0]:
  - Each query starts at 1.0.
  - A `select` adds +0.5 (capped at 2.0).
  - A `reject` subtracts 0.25 (floored at 0.5).
- Multipliers are passed to `fuse_and_rerank` so that re‑search gives more weight to queries the user liked and less to those they rejected.

## Providers (`providers/`)

| Provider | API key required | What it returns |
|---|---|---|
| **Pexels** | `PEXELS_API_KEY` (optional) | Images + videos from Pexels API |
| **Pixabay** | `PIXABAY_API_KEY` (optional) | Images + videos from Pixabay API |
| **Wikimedia** | none | Images + videos from Wikimedia Commons (public domain / CC‑BY) |

Each provider implements `MediaProvider.search(query, client, per_page, media_type)` returning `list[NormalizedMedia]`. Results are cached per (provider, query, per_page) with TTL from config.

---

## Thumbnail Caching (`cache.py`)

- `fetch_thumbnail(url, dest_name)` downloads the thumbnail, stores it under `backend/data/thumbnails/`, and returns a `/thumbnails/…` URL.
- Used by the backend when persisting assets; failures are non‑fatal (empty string returned).

---

## Job Management (`jobs.py`)

- `Job` dataclass tracks: `id`, `status` (queued/running/done/error/cancelled), `stage`, `script_id`, `total_scenes`, `done_scenes`, `media_found`, `scenes` progress, `error`, `paused`, `cancel_event`.
- `run_generation_job` is an async background task that:
  - Splits script → creates scenes.
  - Iterates scenes, calling `populate_media_for_scene` per scene.
  - Supports **pause** (`job.paused = True`) and **cancel** (`job.cancel_event.set()`). Cancellation takes effect between scenes and between thumbnail downloads.
  - After all scenes, runs `matching.apply_board_diversity` (non‑fatal).
  - Partial results are kept if the job is cancelled or fails.

## Configuration (`config.py`)

| Variable | Default | Meaning |
|---|---|---|
| `EMBEDDING_MODEL` | `"all-MiniLM-L6-v2"` | Sentence‑transformers model name. |
| `SEMANTIC_WEIGHT` | `0.6` | Blend weight for semantic rerank. |
| `RRF_K` | `60` | RRF smoothing constant. |
| `TARGET_VIDEO_RATIO` | `0.6` | Desired video‑fraction per scene after diversity pass. |
| `CACHE_TTL_DEFAULT` | `21600` s (6 h) | TTL for most provider results. |
| `CACHE_TTL_PIXABAY` | `86400` s (24 h) | TTL for Pixabay results. |
| `PEXELS_API_KEY` / `PIXABAY_API_KEY` | `""` | Set via `.env`; optional. |

All settings are loaded from `backend/.env` (git‑ignored) using `pydantic_settings`.

## Local Development Quick Start

1. **Backend**  
   ```bash
   cd backend
   python -m venv .venv
   .\.venv\Scripts\activate
   pip install -r requirements.txt
   python -m spacy download en_core_web_sm
   copy .env.example .env   # add PEXELS_API_KEY / PIXABAY_API_KEY if desired
   uvicorn app.main:app --reload --port 8000
   ```
2. **Frontend**  
   ```bash
   cd frontend
   npm install
   npm run dev   # http://localhost:5173
   ```
3. Open `http://localhost:5173`, enter a script title + text, click **Generate**,
   watch the job progress, select/reject assets, and export the storyboard.

## Notes & Gotchas (from HANDOFF.md)

1. Run **one** backend instance on `:8000`; two bind the same port on Windows and cause routing issues.
2. Always use the project virtualenv + `start-app.bat`. System Python lacks deps and may fight for the port.
3. Loopback listener can die (`WinError 64`); restart the backend if polling hangs.
4. Copied virtualenvs break — recreate with `pip install -r requirements.txt`.
5. Wikimedia needs the `User-Agent` header (403 otherwise); thumbnail caching degrades gracefully.
6. Never cache empty provider results; MiniLM ties at ~1e‑7 are not real ties.
7. Pexels is not issuing API keys in this setup — Pixabay + Wikimedia only.
